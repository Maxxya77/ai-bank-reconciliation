로컬 AI 기반 은행·법인카드 회계 대사 시스템

Local-AI Bank & Corporate Card Reconciliation Assistant — 은행 거래와 법인카드 이용내역을 전체 GL과 대사하고 확인이 필요한 거래에 집중하는 프로토타입입니다.

WHY

왜 만들었나

전 직장에서 월말마다 은행계좌와 SAP 원장을 대사했습니다. 모든 거래를 처음부터 직접 비교하기보다 정상 거래를 걸러내고 예외에 집중할 방법을 생각했습니다.

그 실무 경험에서 아이디어를 얻어, 현재 별도의 프로토타입으로 만들었습니다.

HOW

어떻게 만들었나

정형적인 숫자는 Python·JavaScript 규칙으로 검증하고, 비정형적인 표현은 로컬 AI가 보조하도록 역할을 나눴습니다.

규칙 방향 → 금액 → 날짜 → 거래처 → 1:1 → 1:N·N:1 → 예외
AI 컬럼 의미 → 이름 차이 해석 → 후보 제안
RESULT

무엇이 달라졌나

은행·법인카드 거래와 전체 GL을 대사해 정상 거래와 확인이 필요한 거래를 구분하는 프로토타입입니다.

담당자가 정상 거래를 빠르게 걸러내고 실제 확인이 필요한 예외에 집중하도록 돕습니다.

HOW · 상세 구현 방식 보기

규칙 기반 대사

  1. 방향: 은행 출금은 보통예금 대변, 입금은 차변과 비교합니다. 카드 사용은 카드 미지급금 대변을 봅니다.
  2. 금액: 카드 총액을 비용 라인이 아닌 카드 미지급금 총액과 비교해 VAT가 분리된 전표도 연결합니다.
  3. 날짜: 거래일과 전기일의 ±7일 범위에서 후보를 찾고 날짜 차이를 별도 표시합니다.
  4. 거래처: 정확 일치 → 표기 정규화 → 별칭 순서로 확인합니다. GL 적요는 설명에만 씁니다.
  5. 매칭: 1:1을 먼저 확인하고 은행의 1:N·N:1 합계도 검사합니다.
  6. 예외: 금액 차이, 한쪽에만 있는 거래를 분류합니다. 카드 매입대기·승인취소는 일반 오류에서 제외합니다.

로컬 AI의 역할

파일마다 다른 컬럼명을 해석합니다. 규칙으로 방향·금액·날짜 후보를 좁힌 뒤에도 이름이 다른 경우, Streamlit 앱의 Ollama가 거래처 후보를 설명합니다. 추천은 자동 확정되지 않으며 담당자가 확인합니다.

브라우저 데모는 Ollama 없이 정확 일치·정규화·별칭까지만 처리하고 남은 이름 차이를 확인 대상으로 표시합니다.

브라우저는 규칙·수동 컬럼 매핑과 거래처 표기 정규화·별칭을 사용합니다. 알 수 없는 이름은 확인 대상으로 남깁니다. 로컬 Streamlit 앱만 Ollama의 거래처 후보 설명을 제공하며, 최종 확정은 담당자가 합니다.
④ 은행·카드·GL 컬럼 매핑 확인·수정

지금 버전의 한계와 다음 단계

담당자 한 명이 매일 파일을 업로드해서 확인하는 구조라, 별도 서버 없이 파이썬 스크립트 + 로컬 AI로 완결되도록 만들었습니다. 여러 담당자가 같은 데이터를 함께 봐야 하거나 자동으로 매일 실행되어야 한다면 회사가 이미 쓰는 ERP, 회계 시스템에 이 로직을 기능으로 얹는 형태가 되어야 하는데, 그 순간부터는 별도 서버, 배포, 보안 검토가 필요한 사내 시스템 개발 영역이라 지금 범위에서는 과한 설계라고 판단해 제외했습니다.

그룹(1:N/N:1) 매칭은 조합 폭발을 막기 위해 후보 풀을 날짜창(±7일) 내 최대 10건, 그룹 크기는 최대 4건까지만 시도합니다 — 거래량이 매우 많은 환경에서는 날짜창과 그룹 크기 상한을 조직의 거래 규모에 맞게 조정해야 합니다.

자리바꿈(전위) 오류 힌트는 "차액이 9의 배수"라는 통계적 휴리스틱이라, 확정 진단이 아니라 우선순위를 매기기 위한 힌트입니다 (무관한 두 금액도 우연히 9의 배수 차이가 날 확률이 있습니다).

컬럼 매핑은 규칙 기반 키워드 매칭이라, 은행마다 다른 표현(예: "출금액" 대신 "찾으신금액")이나 표 위에 제목, 기간 안내줄이 몇 줄 껴 있는 경우 실패할 수 있습니다. 실제 회사 파일을 처음 넣어볼 땐 "컬럼 매핑 결과"를 먼저 확인하는 걸 권장합니다.
