재무회계 담당자 지원, AI 활용 업무자동화 사례

로컬 AI 기반 은행 및 회계원장 자동대사 시스템

Local-AI Bank Reconciliation Assistant — 회사 PC에서 로컬 AI(Ollama)와 검증 가능한 파이썬 로직으로, 매일 반복되는 은행-원장 대사 업무를 자동화하고 일일 자금 보고까지 만들어내는 프로토타입입니다.

이 도구를 만든 이유

문제SAP 같은 정식 ERP 연동이 안 된 조직에서는 담당자가 매일 은행 거래내역과 회계원장을 손으로 대조하며 불일치를 찾는 게 반복 업무였고, 회사가 OpenAI 같은 외부 API 비용을 지원하지 않을 수 있다는 현실적 제약도 있었습니다.

과정그래서 API 없이 회사 PC 안에서 완결되는 로컬 AI 구조로 설계했습니다. 금액 계산은 100% 검증 가능한 파이썬 로직이 담당하고, AI는 컬럼 의미 추론처럼 판단이 필요한 곳에만 쓰며, 확신이 없으면 억지로 엮지 않는다는 원칙을 세웠습니다 — 금액이 우연히 같다는 이유만으로 서로 다른 거래(예: AWS 10만원과 무관한 Apple 10만원)를 매칭시키지 않고, 적요 및 거래처가 실제로 일치하거나 여러 건의 합계가 정확히 맞아떨어질 때만 자동으로 연결합니다.

결과한 번에 완성된 게 아니라, 실제로 돌려보며 여러 차례 결함을 찾아 고친 과정을 거쳤습니다 (금액 임계값 버그, 입금/출금 방향 오류, 원금+수수료 분할 매칭, 처리 순서 편향 등) — 자세한 개발 과정은 하단 GitHub 저장소의 README에 정리해두었습니다.

지금 버전의 한계와 다음 단계

담당자 한 명이 매일 파일을 업로드해서 확인하는 구조라, 별도 서버 없이 파이썬 스크립트 + 로컬 AI로 완결되도록 만들었습니다. 여러 담당자가 같은 데이터를 함께 봐야 하거나 자동으로 매일 실행되어야 한다면 회사가 이미 쓰는 ERP, 회계 시스템에 이 로직을 기능으로 얹는 형태가 되어야 하는데, 그 순간부터는 별도 서버, 배포, 보안 검토가 필요한 사내 시스템 개발 영역이라 지금 범위에서는 과한 설계라고 판단해 제외했습니다.

그룹(1:N/N:1) 매칭은 조합 폭발을 막기 위해 후보 풀을 날짜창(±7일) 내 최대 10건, 그룹 크기는 최대 4건까지만 시도합니다 — 거래량이 매우 많은 환경에서는 날짜창과 그룹 크기 상한을 조직의 거래 규모에 맞게 조정해야 합니다.

자리바꿈(전위) 오류 힌트는 "차액이 9의 배수"라는 통계적 휴리스틱이라, 확정 진단이 아니라 우선순위를 매기기 위한 힌트입니다 (무관한 두 금액도 우연히 9의 배수 차이가 날 확률이 있습니다).

컬럼 매핑은 규칙 기반 키워드 매칭이라, 은행마다 다른 표현(예: "출금액" 대신 "찾으신금액")이나 표 위에 제목, 기간 안내줄이 몇 줄 껴 있는 경우 실패할 수 있습니다. 실제 회사 파일을 처음 넣어볼 땐 "컬럼 매핑 결과"를 먼저 확인하는 걸 권장합니다.

이 프로젝트가 보여드리고 싶은 것

예상 효과실제로 도입해서 측정해본 결과는 아니지만, 합리적으로 가정해보면 이렇습니다 — 하루 100~150건 규모의 거래를 처리하는 조직이라면, 사람이 하나하나 대조하는 데 보통 20~30분 정도가 들어갑니다(자리바꿈 오타처럼 미묘한 오류는 사람이 놓치기도 쉽고요). 이 도구를 쓰면 계산 자체는 몇 초 만에 끝나고, 사람은 자동으로 걸러진 예외 건 (보통 전체의 5~10% 수준)만 검토하면 됩니다.

다만 위 수치는 정확한 측정치가 아니라 방향성을 제시하기 위한 가정임을 밝힙니다. 또한 이 프로젝트는 특정 도구의 도입 자체를 제안하려는 것이 아닙니다 — 조직마다 은행, 회계 시스템과 업무 프로세스의 형태가 다르므로, 실제 업무에 적용한다면 해당 조직의 환경에 맞춘 형태의 자동화가 필요할 것으로 판단합니다. 이 프로젝트를 통해 보여드리고자 하는 것은 특정 도구 자체가 아니라, 반복되는 비효율을 발견했을 때 이를 방치하지 않고 AI를 활용해 직접 해결책을 설계하고 검증하는 태도입니다.
