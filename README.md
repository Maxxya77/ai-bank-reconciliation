# AI 은행-회계원장 자동 대사 (V2 — 일일 자금 보고 확장)

OpenAI API 없이 Ollama 로컬 AI를 사용하는 포트폴리오용 프로토타입입니다.

## 실행
1. Python 3.11+ 설치
2. `pip install -r requirements.txt`
3. Ollama 설치
4. VRAM 8GB급 노트북이면 `ollama run qwen2.5:7b` (기본값). VRAM 16GB+ 이상이면 앱 사이드바에서 `gpt-oss:20b`로 바꿔도 됨.
5. `streamlit run app.py` (또는 `run_windows.bat` 더블클릭)

## 동작
계좌별 은행 Excel/CSV(최근 30일 롤링) + 계좌 구분 컬럼이 있는 통합 원장 Excel/CSV 업로드
→ 로컬 AI가 컬럼 의미 분석 (계좌별로 원장을 슬라이스)
→ Python이 표준화 및 대사 (금액 오타, 방향오류, 분할/합산 지급까지 탐지)
→ **탭1: 대사 결과** — 계좌별 매칭/예외 대시보드, 미확인 예외를 "확인완료(사유 포함)"로 표시 가능
→ **탭2: 일일 자금 보고** — 계좌별 전일잔액→금일입출금→금일잔액 스냅샷(기준일 = 업로드 데이터의 최신 날짜), 확정/미결 현황
→ **엑셀 다운로드** — "요약(일일자금보고)" + "상세대사내역" 2시트 포맷 파일 하나로 상사에게 바로 공유 가능

AI가 없으면 규칙 기반 컬럼 매핑으로 fallback합니다. CSV는 UTF-8/CP949(EUC-KR) 인코딩을 자동 인식합니다.

## 샘플 데이터
- `sample_bank.xlsx` / `sample_ledger.xlsx` — 단일 계좌 기본 데모 (5가지 예외 유형 학습용)
- `bank_checking_account.xlsx`(주거래 보통예금) / `bank_corporate_card.xlsx`(법인카드 결제계좌) / `ledger_multi_account.xlsx`(통합 원장) — 2계좌 + 일일 자금 보고 데모 (계좌 개수를 2로 설정하고 업로드)

## 왜 데이터베이스가 필요했나 (SQLite)
매일 롤링 30일 창을 통째로 다시 계산하는 구조라, 사람이 어제 "확인 완료(정상)"라고 판단한 예외도
그 거래가 30일 창 안에 있는 동안은 매일 다시 예외로 뜨는 문제가 있음. 그래서 "확인 완료" 판단
자체를 `reviewed.db`(SQLite, 별도 서버 불필요)에 저장해서, 재계산해도 다시 안 뜨게 함. 키는
계좌+상태+거래 내용(날짜·금액·적요)의 해시값이라, 같은 거래는 매번 같은 키로 재현됨.

## v1 → v2 수정 내역
- **[버그 수정]** 기존 매칭 로직은 금액이 정확히 일치해야만 매칭 후보가 될 수 있어서, "같은 거래인데 금액이 다른" 핵심 예외 케이스를 아예 못 잡았음. 적요(이름) 또는 금액 중 하나만 맞아도 후보로 인정하도록 수정.
- 기본 모델을 `gpt-oss:20b` → `qwen2.5:7b`로 변경 (8GB급 VRAM 노트북 기준), 사이드바에서 모델 선택 가능.
- CSV 업로드 시 CP949/EUC-KR 인코딩 자동 fallback 추가.
- "AI로 예외 원인 분석" 버튼 추가 (예외 건에 대한 원인 추정을 한 번의 호출로 처리).
- **[기능 추가]** 금액 불일치 건에 대해 "자리바꿈(전위) 오류 의심"(차액이 9의 배수 — 예: 1051↔1015), "자릿수(0) 오류 의심"(10배/100배 차이 — 예: 20,000→2,000) 힌트를 자동으로 붙임. 단, 이건 확정 진단이 아니라 우선순위를 매기기 위한 휴리스틱임 (무작위 금액 차이도 약 1/9 확률로 9의 배수가 될 수 있음).
- **[중요 버그 수정]** 기존엔 금액을 절대값으로만 비교해서, 입금을 출금으로(또는 반대로) 잘못 기표해도 "정상 매칭"으로 오판정되는 문제가 있었음. 부호까지 비교해서 방향이 반대인 경우 "입금/출금 방향 오류 의심"으로 별도 표시하도록 수정.
- **[기능 추가]** 1:N / N:1 그룹 매칭 지원. 은행 1건(원금+수수료 등)이 원장엔 여러 줄로 나뉘어 계상되거나, 반대로 은행 여러 건이 원장엔 한 줄로 합산 계상되는 경우를 부분집합 합(subset-sum) 방식으로 찾아 "1:N 매칭 (분할 지급)" / "N:1 매칭 (합산 지급)"으로 표시. 후보 풀은 성능/오탐 방지를 위해 날짜창(±7일) 내 최대 10건, 그룹 크기는 최대 4건까지만 시도함.
- **[구조 개선]** 매칭 로직을 다음 원칙으로 재설계함: (1) 1:1 매칭은 반드시 적요/거래처가 일치해야만 인정 — 금액이 우연히 같다는 것만으로는 절대 같은 거래로 단정하지 않음(예: AWS 10만원과 무관한 Apple 10만원을 억지로 엮지 않음). 금액만으로 판단해도 되는 건 오직 그룹(2건 이상) 합계 매칭뿐임. (2) 은행 거래를 순서대로 처리하며 그 자리에서 최선 후보를 채가는 방식(그리디)은, 먼저 처리된 거래가 적합한 후보를 선점해 나중 거래가 진짜 짝을 놓치는 문제가 있어서, 모든 후보 쌍의 점수를 한꺼번에 계산해 점수 높은 순으로 전역 배정하는 방식으로 변경함(중복 금액이 여러 건 있어도 데이터 순서와 무관하게 안정적으로 매칭됨).
- **[V2: 기능 추가]** 다계좌 지원 (1~3개), 계좌별 대사 결과 분리 표시.
- **[V2: 기능 추가]** "일일 자금 보고" 탭 — 계좌별 전일잔액→금일입출금→금일잔액 스냅샷. 기준일은 실제 오늘 날짜가 아니라 업로드된 은행 데이터의 최신 날짜로 산정 (주말/공휴일에 돌려도 마지막 영업일 기준으로 자연스럽게 처리됨).
- **[V2: 기능 추가]** 예외 건 "확인완료(사유 포함)" 표시 및 SQLite 저장 — 롤링 윈도우 재계산 시에도 이미 확인한 건은 "미결"에서 제외됨.
- **[V2: 기능 추가]** 서식 있는 2시트 엑셀 리포트 다운로드 (요약/상세) — 합계는 하드코딩이 아니라 `=SUM()` 수식으로 생성, LibreOffice 재계산 검증 통과.
